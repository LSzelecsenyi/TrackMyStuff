Privacy policy

Effective date: 10 October 2026. This notice describes the Strict Android app and the Strict account service in this version. It is not a legal certification.

Strict is local-first, and sign-in is required

Workout history, plans, the exercise catalog, body weight, measurements, progress photos, goals, and achievements stay on the phone. Strict does not upload that log as a cloud copy. Google sign-in is mandatory, so Strict does process account information on its server.

Data on your phone

You enter training data in the app. A starter exercise list can be created on the phone at first launch. The app stores it in a local database, private photo files, and on-device preferences. Progress photos are not added to the public gallery. Theme, language, and lock-screen preferences are device settings.

Health Connect is optional. If you allow it, Strict reads recent steps, exercise sessions, resting heart rate, heart-rate variability, and sleep duration to show them. Those readings are not written into Strict’s database, are not sent to the Strict service, and are not included in a ZIP backup. Strict does not write them back to Health Connect.

Google account and sessions

  • The app requests a Google ID token. It does not request Gmail, Drive, or contacts. The token is sent to the Strict service to open a session and is not stored as the session itself.
  • The server stores the Google subject as the account key, and the email address when Google says it is verified.
  • The display name is returned at sign-in and kept in the on-device profile. It is not written to a user-name column on the server.
  • The server assigns a Strict user id.
  • The phone stores an opaque session token in encrypted app storage that Android backup excludes. The server stores only a SHA-256 hash of that token. The default session lifetime in the current configuration is 30 days. There is no refresh token.

Purpose: recognise the account and keep Founder access, promotional access, and a verified purchase with that person.

Founder Program

If you join, the server stores the application and, for qualifying workouts, limited metadata: completion time, local date, workout name, duration, exercise count, completed-set count, whether it came from a template, and whether it used external load. A tester report can include the text you write, the app version, and the platform. That upload does not include exercise names, individual sets, reps, weights, notes, body weight, photos, or Health Connect data.

Promotional Pro access

Founder, Early Adopter, Pro Discovery, and Welcome Back are separate programs. Each can be active, paused, or permanently retired on its own. Pausing or retiring Founder does not start Pro Discovery or Welcome Back. Pro Discovery stores one trial per account: activation time and expiry. Welcome Back stores the qualifying workout id you send, activation, expiry, and a cooldown. An existing grant stays valid when its program is paused or retired. A new grant is not issued while that program is paused or retired.

Pro Discovery activity synchronization is optional and off until the signed-in account turns it on. Turning it on is a separate choice from dismissing a privacy-policy notice. If it is on, the app sends the dates of completed native workouts. Several workouts on one date are stored as one date. Imported, abandoned, and in-progress workouts are not sent. The upload does not include exercise names, exercise ids, sets, repetitions, weights, plans, notes, heart rate, heart-rate variability, or other Health Connect readings. The dates are linked to the Strict account. They are used to check eligibility and to stop a repeated grant. They are not an analytics or engagement profile. A full workout log is not uploaded.

Each app installation has a random installation id. That id only separates one install's dates from another's. It is not a login. The account's qualifying dates are the distinct union of its installations. One phone can replace only its own dates. The same calendar date from two phones counts once. Deleting a workout on one phone removes that date from that phone's set only.

Turning synchronization off stops new uploads and deletes the stored dates and sync metadata for that account. It does not delete workouts on the phone, and it does not change an existing Pro Discovery trial's expiry, Founder, Early Adopter, Welcome Back, or a paid subscription. A later opt-in starts empty. Previously deleted dates are not restored. Deleting the account also deletes the dates, the device snapshots, and the permission row. After the trial is activated, the dates and device metadata are deleted. The trial row, if one exists, is deleted with the account. A pseudonymous one-time marker can remain so the same Google account cannot take Pro Discovery again while that program can still be issued. The marker is a keyed HMAC of the Google subject plus a flag. It is not anonymous, and it does not store the workout dates.

An extra device snapshot that has not been refreshed for 18 months is removed when the same account has another snapshot refreshed inside those 18 months. The only remaining snapshot is kept until activation, withdrawal, or account deletion, so the last copy of eligibility progress is not removed for inactivity alone. Eighteen months is a product limit so an abandoned extra phone does not keep dates forever. It is not a statutory retention period. A reinstall creates a new installation id and does not erase the previous installation's dates by itself.

If you delete the account after using a one-time benefit, a marker records which benefits were used so the same Google account cannot take them again while that promotion can still be issued. The marker is a keyed HMAC of the Google subject plus those flags. It is pseudonymous, not anonymous. It does not store the subject, email, name, or workout content. When a promotion is permanently retired, that promotion's flag can be removed automatically. The marker row is deleted only when no flag is still needed. Pausing a program, or filling its capacity, does not remove the marker.

Google Play subscriptions

Paid checkout is not offered until Play products are configured and a real purchase has been tested. When a purchase is verified, the server stores the purchase token, a hash of the token, package name, product id, subscription state, expiry, and order id. Google Play also processes the payment.

Deleting a Strict account does not cancel a Google Play subscription. Billing stays with Google until you cancel it in Google Play. The purchase is unlinked from the deleted account. A purchase that Google Play still treats as entitled, including a purchase made before Strict sent an account tag, can be verified onto one new Strict account. The same purchase is not active on two Strict accounts at the same time. The server keeps the purchase token, a hash of the token, package name, product id, subscription state, expiry, order id, and the time the subscription ended.

The token stays while the subscription is entitled or can still return to an entitled state, including a pause, account hold, or grace period. After the subscription has ended, the purchase row, including the token and order id, is deleted once 24 calendar months have passed from that end. Cancellation time is not the start of that period while paid access continues. A retention hold can keep one row past that date. That hold is not applied automatically, and this notice does not say that 24 months meets a tax, accounting, or dispute duty. Play notification ids are kept so a repeated notification is not applied twice. Those ids do not contain the purchase token or the Strict account.

Feedback, backups, and logs

Send feedback opens your email app with a draft to laszlo.szelecsenyi@gmail.com. The draft includes the app version, Android version, and device manufacturer and model. Strict does not send the email. Your email provider handles it if you send it.

A ZIP backup contains the structured training data and progress photos you export. You choose the file location. Strict does not delete that file later. Health Connect readings and the session token are not in the ZIP. Android Auto Backup and device-to-device transfer of app data are turned off.

Application logs record error codes and rejection reasons. The sign-in diagnosis does not record the ID token, Google subject, email, or name. Purchase tokens are not written to those application logs.

How long data is kept

  • Training data on the phone remains until you delete it, delete the account, or uninstall the app.
  • The server account, sessions, Founder records, promotional grant rows, and Pro Discovery workout dates are deleted when the account deletion succeeds.
  • Pro Discovery workout dates and device sync metadata are also deleted after that account's trial is activated, and when the account turns synchronization off. They are not kept for the 24-month purchase period, and they are not kept for analytics.
  • A one-time benefit marker remains while that promotion can still be issued. After the promotion is permanently retired, its flag can be removed, and the marker row is deleted when no flag remains.
  • An active or still-recoverable Play purchase remains so it can be verified onto one Strict account. An ended purchase row is deleted 24 calendar months after it ended, unless a retention hold is set.
  • An exported ZIP remains wherever you saved it.

Account deletion

In the app, open Settings and choose Delete account. The button stays disabled until you confirm. Strict asks Google for a fresh sign-in. Local data for that account is removed only after the server confirms deletion. The same Google account can sign in later as a new empty account. Founder recognition, a used promotion, and the old workouts are not restored. A Play purchase that is still entitled can be verified onto that new account, and it cannot be active on two accounts at once.

If you no longer have the app, use Delete your Strict account on this site. That page is part of this server build. It is not a claim that the public production address is already online.

Sign-out and uninstall do not delete the server account.

Your requests

You can delete individual measurements, photos, and workouts in the app, export a ZIP of local training data, and delete the account as described above. There is no separate self-serve download of the server profile.

Security

The release app is configured to call the API over HTTPS. The session token on the phone is encrypted, and the server stores a hash of it. The local database is in app-private storage. This notice does not claim a separate encryption layer for that database, and it does not claim a security certification.
